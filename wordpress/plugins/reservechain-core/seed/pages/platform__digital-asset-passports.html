What a passport is

Not a page about an asset. A record of one.

A Digital Asset Passport is generated, not written. Nobody edits a passport directly. It is assembled from the registry records for one specific lot, container or bobbin. A passport can therefore never state more than its evidence supports, and every statement in it can be traced to a document whose fingerprint you can check.

01

One passport per controllable unit

A passport exists for each lot, each container and each bobbin. The copper lot and its Box no. 20 each have their own passport. Each of the 30 nickel bobbins has one too.

02

Permanent identifier

Identifiers follow the pattern RC-[metal]-[type]-[sequence], for example RC-NI-COL-000008. An identifier is never reused, even after a unit is released or retired.

03

Parent and child links

Lots link down to their containers or bobbins, and units link up to their lot and program. Evidence attached at lot level is visible from every child unit.

Merkle integrity

One hash that commits to everything

Each passport carries a SHA-256 Merkle root. Its leaves are a fingerprint of the passport's public fields plus the fingerprint of every linked document. Change a purity value, swap a certificate scan or remove a receipt, and the root changes.

The root is shown on the passport and included in the JSON export. Third parties can store it and compare it later. It is also a compact value suitable for anchoring on a public ledger.

Access

QR, web and machine-readable JSON

QR access

Each passport has a QR code that resolves to its permanent URL. In the proposed custody model, the code would be printed on the unit's label, so whoever handles a container can open its record.

Downloadable evidence

Add ?format=json to any passport URL to download the full passport: fields, lifecycle, document fingerprints and Merkle root. The same data is served at /rc/v1/passports/{no}.

Independent check

Hash a document you hold with any SHA-256 tool, or use the verification tool, then compare the result with the fingerprint listed in the passport.

History and versioning

A passport remembers

A passport's past states remain part of its record. Each publication is a version, each version passed four-eyes approval, and every transition is in the tamper-evident audit trail.

  • Replacing a document creates a new document version, and the passport root changes visibly.
  • Unpublished or archived passports are withdrawn, never hard-deleted.
  • Lifecycle stages record when evidence was added and who approved it.
  • Statuses such as "verified" or "in custody" appear only when a linked, approved record exists.
