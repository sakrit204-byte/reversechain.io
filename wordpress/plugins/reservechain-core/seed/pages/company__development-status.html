How to read this board

Three states, one definition of done

An item is "completed" only when it exists, can be demonstrated and has been tested. Work that depends on an independent party (laboratory, custodian, insurer, auditor, counsel) stays "planned" until that party is appointed and its evidence is approved.

[rc_status s="provided" label="Completed"]

Completed

Built, tested and demonstrable in the current pre-launch build. Does not imply production deployment or public activation.

[rc_status s="in_development" label="In progress"]

In progress

Actively being prepared. Outcome and timing remain subject to advisers, owner inputs and final approval.

[rc_status s="proposed" label="Planned"]

Planned or pending

Defined in the proposed framework but not started, usually because a third party has not yet been appointed or a written authorization is required.

No-launch conditions

What has to be true before anything goes live

Launch is a written gate, not a date. The proposed framework blocks activation while any of these conditions remain.

  • Unresolved critical defects or critical smart-contract audit findings.
  • Unaccepted high-risk security findings.
  • Failed supply, module or redemption reconciliation.
  • A failed backup-restore test.
  • Incomplete transfer of keys, roles and accounts to issuer control.
  • Missing written authorization for any gated module.

Integrity

This board is governed like a registry record

Status changes on this page pass through the four-eyes workflow and are written to the tamper-evident audit trail. The live chain status is shown here so that any silent rewrite of history would be detectable.
