Status vocabulary

What each badge means, and does not mean

Programs and passports use the same small set of statuses. Labels such as Verified, Certified, In Custody, Tokenized, Available or Redeemable appear only after the status has been authorised. None has been authorised.

Proposed[rc_status s="proposed"]Designed and described. No implementation or approval yet.
In development[rc_status s="in_development"]Being built or assembled, for example registry records and passports.
Pending verification[rc_status s="pending_verification"]Evidence has been supplied, for example an owner-supplied certificate, but has not been independently confirmed.
Pending[rc_status s="pending"]No evidence supplied yet. The field stays empty rather than estimated.
Not applicable[rc_status s="not_applicable"]The field does not apply to this asset class or unit.
Future category · pre-launch[rc_status s="proposed" label="Future category · pre-launch"]A concept only. Excluded from every count, total and reserve figure.

Anatomy of a program record

Separate records, linked by identifiers

A program is not one database row. It is a tree of separate record types, each with its own evidence and its own status, so a claim about one box or one bobbin never depends on the whole lot.

01

Program

Material category, rules, unit of control and a configurable token-series link.

02

Lot or batch

Batch number, laboratory report, declared and tested quantities, and the purity basis.

03

Container or coil

Unit identifier, seal number, net weight, location, and its own redemption status.

04

Evidence records

Ownership, laboratory, custody, valuation and insurance records, each fingerprinted.
